# Geoapify API and operation matrix

This document limits the package to independently useful, documented operations. OpenAPI contracts establish request/schema evidence; they do not establish live API behavior or a user's account entitlements.

## Contract sources and discrepancies

The official [OpenAPI catalog](https://github.com/geoapify/geoapify-openapi-specs/blob/e8255e614648084d86bae2155c20347d5203ec1d/api-specs/index.json) was checked first on 2026-09-30. Only the two Batch 1 specifications below were loaded. Both are pinned to Geoapify's OpenAPI repository commit [`e8255e614648084d86bae2155c20347d5203ec1d`](https://github.com/geoapify/geoapify-openapi-specs/tree/e8255e614648084d86bae2155c20347d5203ec1d): [forward geocoding spec](https://github.com/geoapify/geoapify-openapi-specs/blob/e8255e614648084d86bae2155c20347d5203ec1d/api-specs/forward-geocoding/forward-geocoding-api-openapi-specs.json) and [reverse geocoding spec](https://github.com/geoapify/geoapify-openapi-specs/blob/e8255e614648084d86bae2155c20347d5203ec1d/api-specs/reverse-geocoding/reverse-geocoding-api-openapi-specs.json).

Human documentation reviewed on the same date: [catalog](https://apidocs.geoapify.com/docs/), [forward geocoding](https://apidocs.geoapify.com/docs/geocoding/forward-geocoding/), and [reverse geocoding](https://apidocs.geoapify.com/docs/geocoding/reverse-geocoding/). Their explanatory prose and embedded generated API reference were considered separately; where a parameter appears only in the embedded reference/schema and not in the human-facing parameter prose, that distinction is recorded below. The implementation-style decision follows n8n's guidance on [node overview](https://docs.n8n.io/connect/create-nodes/overview/), [choosing a node-building style](https://docs.n8n.io/connect/create-nodes/plan-your-node/choose-a-node-building-style/), and [verification guidelines](https://docs.n8n.io/connect/create-nodes/build-your-node/reference/verification-guidelines/), accessed 2026-09-30.

Recorded differences: the contracts define both `ApiKeyInQuery` (`apiKey`) and `ApiKeyInHeader` (`x-api-key`) security schemes, while human prose/examples show query authentication; this integration uses the supported `x-api-key` header through n8n credentials. The contract models filters and bias values as arrays in places where human examples serialize them as strings; Batch 1 sends the forward country restriction as `filter=countrycode:<comma-separated-codes>`, as described in the forward documentation's prose filter section. The reverse schema and embedded reference include locality/building as parameter enum values absent from the reverse human-facing parameter list, so those choices are not exposed. Country restriction is forward-only in the UI; the shared form does not send it on reverse requests. The response wrapper is modeled as a GeoJSON FeatureCollection.

No live Geoapify request has yet confirmed these contracts against an account. Do not infer plan availability, exact rate limits, postal deliverability, or observed error bodies from the schema or tests.

Both operations use the same declarative REST routing design. The selected operation supplies a fixed absolute URL expression. A one-request `send.paginate` callback validates values before `makeRoutingRequest`, then catches and sanitizes transport errors so Continue On Fail can return a paired error item; this preserves behavior that a `preSend` hook could not provide in n8n core 2.30.3 because `preSend` failures bypassed the callback's catch. `postReceive` validates and normalizes the response. The callback makes at most one request per input and does not page, loop, or retry. No custom `execute` or custom transport is used. Expressions are supported in fields/options. The node does not define a generic API operation. n8n's host loader may add a separate Custom API Call menu entry for generic-auth credentials; that affordance is host-provided. The node defines no `requestDefaults`, leaving each selected endpoint URL explicit.

### Shared authentication and output contract

The single `Geoapify API` credential stores a password-masked API key and injects `x-api-key` in the request header. Runtime code must not read environment variables or the filesystem. The node uses the credential for both operations. The credential test is a documented GET to `/geocode/search?text=Berlin&limit=1`. Geoapify's forward and reverse pricing sections state that one request equals one credit, so this credential test consumes one credit.

The node's selected output is either one item per returned feature or one item containing the raw FeatureCollection. In feature mode, the response's `properties` are copied to top-level `json`, while `geometry` is retained. This carries service-returned IDs, formatted/structured address values, coordinates, rank and confidence values through without claiming that confidence guarantees postal deliverability. In one-item-per-match mode, a successful FeatureCollection with no features maps to `[]`; this is successful empty output, not an API error or fabricated feature. In raw mode, every input produces one item containing the full FeatureCollection, including an empty `features` array. Native n8n **Always Output Data** affects the empty per-match mode, where it may add its configured empty item at the workflow boundary. Multiple matches are never reduced to an arbitrary first match. In the pinned n8n routing fixture, two inputs produced four results with paired-item indexes `0,0,1,1` for successful results and `0,1,1` for one Continue On Fail error and two successful results, confirming linkage in those tested paths; see [testing evidence](testing.md).

### Request limits and failure behavior

Requests have a 30-second timeout and the error-guard callback makes at most one request per input item. It does not perform API pagination or retry automatically. Users may configure bounded n8n Retry On Fail behavior for their plan and workflow. Error handling retains useful service messages and sanitized rate-limit timing where available, while excluding credential values and authenticated URLs. The API's exact account-specific quota and rate-limit limits remain outside this contract.

## Deliberately deferred

This batch does not implement autocomplete, asynchronous batch geocoding, Places, Place Details, Routing, matrices, route optimization, isolines, map matching, static maps, tiles, elevation, geometry operations, MCP, or triggers. Their planned batches are tracked in [the handoff roadmap](batch1-handoff.md#roadmap).
